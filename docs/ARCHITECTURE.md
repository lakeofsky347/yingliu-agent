# 映流智能体架构

应用提供项目首页、对话导演、工程编辑、本地制作，以及独立的多模态协作面板。模型中心支持多个连接、模型与创作角色。所有应用代码、数据包、依赖和打包入口在本目录，运行不依赖 DSH 的会话、插件装载器或凭据。

## 应用边界与模块

| 模块 | 职责 |
| --- | --- |
| `src/desktop/` | 单实例 Electron 壳、无 Node 的编辑器、主窗口 IPC 校验、系统加密凭据、文件选择与关闭前保存 |
| `src/agent/` | 导演工具循环、按工程串行的运行生命周期、一次性审批、成功结果回执与恢复结算、创作计划和项目预算 |
| `src/app/application.ts` | 白名单应用路由；连接模型中心、对话、媒体任务与协作服务；关闭时保存状态、停止本地活动并排空已有调用 |
| `src/models/`、`src/app/model.ts` | 版本化连接/模型/角色注册表、协议适配器、凭据引用、JSON/SSE 文本传输；兼容旧 custom 配置，fixture 只供测试显式注入 |
| `src/jobs/` | 独立持久媒体任务、提交对账、远端查询、下载校验、结果采用、停止观察与远端取消 |
| `src/workflows/` | 固定导演/画面/配音/检查流程、受限并发、候选结果、恢复与 CAS 提交 |
| `src/media/` | 真实视频探测、流式导入与哈希、CFR 代理、统一片段时间映射 |
| `src/app/conversation.ts` | 持久 turn 状态、上下文预算、读取回执、有限修复、候选工程校验与一次事务提交 |
| `src/app/archive.ts` | v2 `.yingliu` 流式 ZIP 备份，兼容导入 v1；SHA256 清单、路径/解压量限额与新 ID 原子导入 |
| `src/host/project-hub.ts` | 多工程注册、选择、重命名、复制、归档及恢复；每工程独立服务 |
| `src/host/service.ts` | 工程队列、CAS、渲染/声音协调、原有本地制作任务记录、视频片段操作与白名单重试 |
| `src/host/store.ts` | 安全路径、不可变完整版本、原子 head、单调 revision、修复投影、持久 Undo/Redo、素材导入 |
| `src/core/`、`src/shared/` | v2 工程、稳定业务 ID、整数帧与有理数 FPS、镜头图、参数、视频/声音片段 |
| `src/client/` | 首页与简报、创作对话、模型中心、LiteGraph、源码/素材/视频/音轨、媒体与协作任务、历史/导出 |
| `src/runtime/`、`src/host/renderer.ts` | 按帧场景契约、软件 Canvas 可复现捕帧、本地浏览器、FFmpeg/ffprobe 与实际媒体 QA |

镜头由 HTML/CSS/ES module 构成，按 `render(ctx)` 独立求值。节点图表达线性播放主链、镜头及素材绑定；不是任意模型工作流执行器。可视属性与模型共用稳定 shot ID；不会从任意 JS 自动反解完整图层或关键帧时间线。

## 完整版本与提交点

工程保存到应用 `dataDirectory/projects/`；外部目录打开也使用相同存储协议。`.studio/versions/<id>.json` 保存工程与所有镜头源码的完整不可变版本，`.studio/revisions/<revision>.json` 将单调业务版本定位到快照。`.studio/state.json` 保存当前版本以及 Undo/Redo 指针。

提交先验证项目、全部 source 和素材引用，再写快照与版本索引，最后原子切换状态指针。指针 rename 是整次工程+源码修改的提交点。`project.json` 与 `shots/` 中的 HTML/CSS/JS 是当前版本投影；提交后投影失败时，重新打开从 head 修复，不将半组投影当作工程事实。临时文件和目录使用同步写入，但没有机器断电注入测试。

同工程 API 和后台任务提交共用串行队列。save/apply/saveSource/restoreSource/undo/redo、rename、retry/job.retry、import/audio 和 video.clip.save/remove/extract 必须提供 expectedRevision，在队列内实际写入前检查；省略或过期版本均拒绝。客户端导入与音轨编辑使用已保存版本，智能体内部素材登记也先读取版本再提交。Undo/Redo 将以前内容提交为新的 revision，版本号不回退；源码、音轨、素材引用和模型修改一起恢复，同一生成任务可归为一个撤销步骤。

素材文件由 UUID 命名并视为不可变，历史恢复其引用，不删除旧素材。还未提供快照/素材垃圾回收或多窗口协作写入。

CLI、桌面、浏览器服务和默认 `createApplication` 共用同机所有权协议。入口在加载配置、修复工程或恢复任务之前取得数据目录与工程基目录的 OS listener 锁；应用显式借用入口 lease，嵌入应用默认自行持有 lease。实际工程根目录在打开、投影修复、staging 清理或首次写入前动态加锁，因此不同 profile 不能同时打开同一外部工程。目录真实身份统一符号链接别名，同一 lease 复用监听端口；动态根目录冲突立即 BUSY，不在持有其他锁时无限等待。退出和启动失败都先排空已接受操作与自有任务，再释放 lease。此协议不协调其他机器、其他网络命名空间或未采用它的旧应用。

导出先冻结 project revision，并按该 revision 读取整组源码与素材，复制到独立快照再渲染；后续工程修改不会让导出混用新源码。结果记录输入版本、哈希、帧数、音视频规格和检查报告。每次导出产生新目录，旧成片可以继续播放。

## 模型中心与创作入口

应用数据目录的 `model-registry.json` 保存 version 1 的 `ProviderConnection`、`ModelDefinition` 和 `RoleBinding`。连接记录协议、地址、认证方式、凭据引用、超时与并发设置；模型以本地稳定 ID 关联连接，另保存供应商模型名、输入/输出模态及参数；角色为 director、scene、vision、image、video、speech。一个连接可以配置多个模型，角色可以分配给不同连接。

首批协议为 Chat Completions、Images Generations、异步媒体网关 v1 与 Speech 兼容接口；供应商必须实现对应契约。目录探测失败时仍可手动配置模型，连接检查不触发生成。文本 JSON/SSE 仍由 `ProviderManager` 处理，媒体协议由 `src/models/adapters/media.ts` 处理。语音角色存在时使用其 Speech 连接；未配置时沿用现有本地语音/兼容 TTS 设置。

旧 `provider.json`、custom 凭据引用和 TTS 配置保留读取。首次没有注册表时，custom 配置迁为默认文本连接与模型，并绑定 director/scene；已有注册表不会被旧配置覆盖。界面中的“快速配置兼容文本接口”仍只编辑 custom。正常应用目录不暴露 demo；测试 fixture 必须显式启用。

对话导演与“协作制作”仍是两套用例执行器：对话继续使用受限 JSON 工具计划；协作服务使用固定角色流程和持久步骤。两者共用模型注册/文本传输、工程读写队列与 expectedRevision 提交边界。工作台的传统文本生成入口通过应用创作处理器进入对话；没有把所有旧对话动作改成多模态工作流，也没有把分镜图改成通用流程编辑器。

## 对话与三类任务生命周期

讨论仅持久对话，不创建或修改工程。创建向导先保存用户简报；对话模型修改先形成完整候选工程，校验全部动作后一次 create/apply 提交。计划格式、工具校验和已知版本冲突可在最多四轮内通过真实读取回执修复；未知 I/O 或无法判断是否提交的失败不自动重投事务。预览失败保留已提交版本与失败 turn。回合状态为 pending/succeeded/failed/cancelled/interrupted；重试沿用原请求的图片选择并重新读取当前工程。

任务记录各自承担不同恢复语义：

| 记录 | 位置 | 中断与重试 |
| --- | --- | --- |
| 原有本地制作任务 | 工程 `.studio/tasks/<id>.json` | 重启把运行记录标为 TASK_INTERRUPTED；只允许白名单任务参数重试，真实计费配音不自动重放 |
| 媒体生成任务 | 应用 `media-tasks/<id>.json` 与对应产物目录 | 提交前持久 request ID、配置快照与输入哈希；视频按原请求 ID 对账、按远程 ID 恢复查询；下载失败只重新取产物 |
| 多模态工作流 | 应用 `workflows/<id>.json` | 重启后暂停，用户恢复时复用完成步骤；响应不确定的配音不会自动再次合成 |

媒体任务本地 phase 与 observation、远程 queued/running/succeeded/failed/cancelled 独立。ready 表示校验后的候选结果，complete 表示已采用；采用使用当前 expectedRevision 并以任务来源记录实现幂等。停止等待和应用退出不确认云端取消；只有网关明确回执才记远端 cancelled。同步生图响应丢失无法对账时保留 unknown，不自动再次计费；`media.retry` 不重投已经结束的生成。

成功的同步 JSON/binary 产物持久化后，下载/检查失败可以直接复用回执中的产物；本地请求 ID 不作为远端任务 ID 轮询。完整内嵌 Base64 结果同样直接复用。真实异步任务的 URL 结果仍按真实 job ID 查询，允许刷新失效下载地址。

每个媒体任务保存地址、模型与参数快照，后续查询重新解析凭据引用以支持轮换。在用连接/模型受到删除和关键配置修改保护；不从模型参数接受密钥或任意认证头。下载、校验和采用失败不会覆盖工程编辑。

Workflow 的主记录与独立成功回执使用文件 fsync、原子 rename 和可用的目录 fsync。文本回执绑定步骤、角色、请求和图片哈希；配音回执保留已校验的音频资产。主记录结算失败后优先消费成功回执，工程已提交但响应丢失时按 workflowApplications 对账；没有成功回执的未知配音不自动重投。测试覆盖系统调用与检查点故障、重启和实际调用次数，不宣称实机断电验证。

固定协作流程先规划导演任务，再执行代码或图片/视频生成及可选配音；候选素材完成后，先完成已启用的视觉检查，再 CAS 合并。最多两个制作步骤并行，媒体生成还遵守服务与连接并发限制。空工程可以先提交初始化分镜。视觉检查从不可变候选工程、源码及素材快照中捕获所选镜头最多三个实际关键帧，发送给 vision 角色并记录帧号/SHA256/意见；捕帧或检查执行失败不提交候选结果，已经建立的初始分镜仍保留。源码检查不能替代视觉证据，检查意见也不代表完整影片质量验收。

正常工作流自动按起始 revision 合并；冲突保留 awaiting-apply，由用户显式采用到当前版本，且保留非目标镜头。启用视觉检查时，显式采用会基于最新 revision 重新构建候选快照并重新审片，不能用旧候选帧的检查结果确认新的合并内容。显式恢复失败媒体步骤可以创建新请求；已完成步骤和产物继续复用。任务数量上限可用。当前没有可靠的模型预报价，设置 maxCost 会在任何模型请求之前暂停；完整费用显示未知，可用的媒体费用只作为独立小计，不等于总费用。

关闭前编辑器尝试保存工程；未保存源码、角色库、预算或保存失败可保留窗口。角色与预算草稿需要保存或显式放弃，轮询不覆盖编辑值，异步响应绑定原工程。离开面板、返回首页和切换工程也检查这些草稿；智能体启动、批准、拒绝后继续和恢复先通过 controller 的保存/草稿检查。应用停止对话、本地渲染与协作活动并等待记录写入，媒体任务保留远程标识供重启查单。退出后无本地后台工作或逐帧断点续渲，也不会默认删除任务或取消远程生成。

## 视频、工程 v2 与工程包

新工程使用 schemaVersion 2。读取 v1 时补齐视频片段结构，写入 v2 并保留镜头 ID、源码、素材及历史；未知格式明确拒绝。v2 不能交给只支持 v1 的旧程序写入。

视频导入先用 ffprobe 读取真实尺寸、时长、帧率与音轨，再生成固定帧率、全关键帧 H.264/AAC MP4 代理。资产的 path 指向代理，originalPath 指向保留的原始文件，两者各有哈希。每镜一个主 VideoClip，记录裁入/裁出、速度、cover/contain 和静音/保留原声；提取原声创建独立音轨并静音片段。生成视频默认静音。

播放按工程整数帧与有理数 FPS 映射到源视频帧，随机跳帧等待解码完成后才捕获；预览和导出使用同一运行时映射。镜头长于裁剪片段时保持末帧。宿主先画视频，再运行代码图层；ctx.hasVideo 允许源码跳过不透明底色，已有全屏不透明自定义画面仍会覆盖视频。音频混合使用相同裁剪/变速和镜头位置。

路径导入、哈希、媒体下载及本地路径工程包采用分块处理。视频默认每文件最大 512 MiB，环境设置可降低；视频 Base64 入口只接受不超过 32 MiB，较大视频使用明确选择的本地路径。原始文件与代理是工程资产，不能作为临时缓存删除；现阶段不提供素材垃圾回收。

`.yingliu` v2 包只保存当前工程、对应源码、引用素材（包括视频原始文件与代理）和哈希清单；不打包整段 Undo/Redo 历史、运行任务、模型连接、凭据或临时下载 URL。导入同时接受 v1/v2 包，验证清单后创建新工程 ID。默认单文件 512 MiB，总量小于 ZIP32 的 4 GiB 界限（保留 1 MiB 元数据空间），最多 256 项；调用可降低 fileBytes/totalBytes。浏览器 Base64 工程包仍限 64 MiB，较大包使用桌面路径入口。不同产品工程包完整互通不在本版承诺内。

## 场景执行与凭据边界

编辑器使用随机端口的 `127.0.0.1` origin，HTTP 写 API 要求随机 token 和相同 origin；桌面 IPC 只接受该窗口的主 frame、匹配 frameTreeNodeId 与白名单方法。编辑器 contextIsolation/sandbox 开启，Node 关闭。

画面服务使用 `localhost` origin。Electron 强制 site-per-process，使模型场景与编辑器处于不同系统 renderer 进程；实际验收还检查二者 PID 不同。画面没有 preload bridge、Node 或 IPC，网络由 CSP 限制，资源服务只开放 runtime、媒体素材、检查图与成片，拒绝 project、凭据和日志。子 frame 导航和新窗口受控。

主画面与缩略帧以 ready/frame 回执和十秒 watchdog 判断无响应，后续 render 请求不能不断延迟这个界限。原生 resetScene 仅处理当前编辑窗口关联的 localhost child frame，排除 editor PID，再通过限定的 Chrome 调试协议中止对应 iframe target 的 JavaScript，并临时导航到空白页；重载采用最新已保存源码，可恢复无限循环场景，编辑器保留。没有宣称 CPU/内存配额、任意恶意代码完全隔离或通用执行资源沙箱。

桌面 Key 用 safeStorage 加密持久化，注册表只保存凭据引用，界面只读 hasKey/credentialStatus；不可用时阻止需密钥的操作，不降级到明文。无密钥服务和手动制作可继续使用。对话图片默认只有元信息，实际发送需模型图片能力、enableVision、本轮明确图片 IDs 与上传授权，同时校验路径、尺寸、类型和字节限制。图生视频也只发送本轮选中的工程图片；工作流视觉检查的渲染帧须另有本轮明确授权。

## 工作包与可移植性

`packs/foundation` 是本应用自己的六份 recipe、两份交付 profile 和制作模板；manifest 保留来源哈希。简报保存选择与版本，导演读取实际 recipe 内容作为创作约束；recipe 仍为 design_proposal，需对生成画面另行验证。

macOS 包包含 Electron、应用、fflate 与 playwright-core；Chrome/Chromium、FFmpeg、ffprobe 和系统字体通过本机检测或用户指定提供。源码和已打包应用的迁移验收与真实云供应商、跨机器安装、签名公证分别记录，不能互相替代。
