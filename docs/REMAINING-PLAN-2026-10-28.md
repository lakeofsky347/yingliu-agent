## 施工中新增的边界修复

- Workflow 的导演、场景与审片文本同样保存成功回执；回执绑定步骤、请求和图片哈希。无效输出可修复重试，损坏回执保留字节并停止。
- 工程完成态与最后落盘之间的短暂窗口会排空后再接收下一项任务；关闭时等待已接受的准备与保存请求，关闭期间不会留下没有执行器的运行中记录。
- 所有权保护覆盖外部工程打开前的投影修复和 staging 清理，避免只保护默认目录却遗漏实际工程。
- 桌面第二次关闭请求也必须等待清理完成，不能仅用“正在关闭”状态放行退出。
- 缺失或非法供应商 usage 不当成零 token 费用；未知导演费用也记入项目账本。
- 验收阶段分别隔离工程目录，防止 package/native/media 阶段相互污染；明确检查实际 renderer sandbox 与系统凭据后端。
- 场景 render 写入实际文字和字号后强制布局并再次等待字体就绪；延迟新字形回归验证修前失败、修后通过。PNG严格哈希继续保留，失败报告仅增加阶段、帧、哈希和有界像素统计。
- 媒体轮换密钥测试等待实际GET到达；后台任务fixture按真实终态与对应持久化记录等待，不以固定延时或次数代替完成。
- 搬迁包界面验收在预览及保存源码后，等待本次新任务 ID、类型与工程版本匹配后再检查终态；真实失败或取消立即失败，播放器等待实际握手就绪。补齐仅含枚举与整数的失败诊断，保留原 Windows 失败原因尚不能唯一确定的限制。
- Windows 浏览器预检使用真实 Playwright 启动和版本读取，替换不适用 GUI 程序的命令行版本探测；原生截图有明确超时与阶段定位。
- 预览切换版本时替换 iframe 上下文，拒绝旧窗口排队消息；布局阶段先重置状态，成功帧清除旧错误。三项真实 React/Chromium 顺序回归均已验证修前失败、修后通过。
- Linux 钥匙环守护程序以单一后台任务启动；只按当前 shell 的自有任务发送信号，TERM 后有界升级 KILL，避免后台管道 PID 不匹配导致验收完成后退出挂起。
