# 工程包 v2 与大小限额

`.yingliu` v2 仍采用 ZIP，包含当前工程、每个镜头的源码和工程引用的素材，并以 SHA256 清单校验内容。视频同时备份 `Asset.originalPath` 指向的原始容器和 `Asset.path` 指向的恒定帧率代理；两份文件分别计入大小限额。缺失任一引用文件时拒绝备份或恢复。

恢复兼容 v1 工程包。导入创建新的工程 ID，保留镜头、素材、视频片段的稳定 ID，通过存储层迁移为工程 v2。备份不携带对话、撤销历史、运行任务、供应商配置或已导出的成片。

## 默认限制与硬上限

| 范围 | 默认值与不可突破的上限 |
| --- | --- |
| 单个素材文件 | 512 MiB（536,870,912 字节）；原始视频与代理分别计算 |
| 包文件大小、实际解压总量 | 各不超过 4 GiB 减 1 MiB（4,293,918,720 字节），为 ZIP32 目录与头部保留空间 |
| 单份工程、源码或清单 JSON | 24 MiB；设置更小的单文件限额时采用更小值 |
| 文件数量 | 256，包含清单 |
| 浏览器 JSON/base64 包传输 | 64 MiB 的 ZIP 字节；大包通过桌面应用的本地文件对话框操作 |

桌面路径模式逐块写入 ZIP；恢复逐块解压到新建临时目录，校验后通过本地文件复制创建工程。媒体不会先全部转为 base64 或载入一个缓冲区。浏览器小包模式保留 base64 兼容路径，因此仍有独立的传输上限。

## 每次操作的限额 API

`app.exportProject` 与 `app.importProject` 均接受可选的 `limits`：

```ts
// 限制本次备份：单文件 128 MiB，整个包和实际解压总量各 1 GiB。
await application.route('app.exportProject', {
  projectId,
  path: '/absolute/path/影片.yingliu',
  limits: {
    fileBytes: 128 * 1024 * 1024,
    totalBytes: 1024 * 1024 * 1024,
  },
});

await application.route('app.importProject', {
  path: '/absolute/path/影片.yingliu',
  limits: {
    fileBytes: 128 * 1024 * 1024,
    totalBytes: 1024 * 1024 * 1024,
  },
});
```

对应的应用内部函数是 `exportProjectArchive(backend, input)` 和 `importProjectArchive(backend, input)`。省略字段使用默认值；指定值必须为正整数字节数，且只能下调，超过硬上限、零、负数、小数或错误类型均拒绝。该配置只影响本次调用，不写入工程或全局设置。目前原生文件对话框使用默认限制，尚无图形化限额编辑器。

`fileBytes` 约束每个条目；JSON 还受 24 MiB 硬上限约束。`totalBytes` 同时约束输入或输出 ZIP 字节数，以及所有解压后条目字节之和。ZIP 头部和清单也占空间，不能把 `totalBytes` 恰好设为素材字节合计。限额检查覆盖预检和实际流式处理，不依赖 ZIP 声明的原始大小。

## 失败与完整性

导出写入临时文件，完成后再次检查工程版本；成功才原子替换目标包。失败会移除临时输出，保留目标位置已有文件。恢复先检查路径、重复条目、实际大小、ZIP 结束目录、清单和每文件 SHA256，全部通过后才创建工程；临时解压目录在成功或失败后均清理。工程内符号链接、越界路径、未支持的包版本和截断文件会被拒绝。

65 MiB 素材往返测试仅验证流式备份与字节一致性；视频解码、逐帧渲染与真实供应商生成分别验收。
